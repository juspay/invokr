Crash recovery

Time What happens The row, in the database
t+0ms worker_b2e7 claims exec_4f2c and starts delivering RUNNING · worker_b2e7
t+340ms worker_b2e7 is SIGKILLed mid-delivery the transaction never commits
t+340ms PostgreSQL rolls the whole claim back with it QUEUED · worker_id NULL
t+520ms the next poll from worker_c9d4 picks it straight up RUNNING · worker_c9d4
There is no monitoring worker watching for stuck jobs. The claim and the delivery are the same transaction, so a worker that dies never committed either one.

the on-ramp

You do not have to run anything

Library mode: Invokr embeds in a Rust service you already operate, on the Postgres you already have. 

let client = InvokrLibraryClient::new(
    pool, "sched_", &enc_key, None)?;

client.provision_workspace("orders").await?;

client.create_job("orders", "send-receipt",
    input, 3,
    JobTrigger::Delayed { run_at },
    Some(&key)).await?;

let handle = client.start_worker(
    MySchemas, WorkerConfig::default());
  • No new service. The worker is a task in your process
  • No new infra. Your Postgres, with a table prefix so our tables stay out of your way
  • Service mode is the same code with an HTTP hop in front. You can start embedded and move to service when you have a reason.
