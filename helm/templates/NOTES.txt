────────────────────────────────────────────────────────────────────────
1. VERIFY pg_cron IS ACTUALLY LIVE
────────────────────────────────────────────────────────────────────────
Invokr does not schedule CRON jobs itself -- it delegates to the pg_cron
Postgres extension. If pg_cron is not loaded, everything below will look
healthy and CRON jobs will simply never fire.

  psql "$INVOKR_DATABASE_URL" -c "SELECT * FROM cron.job;"

An error here means the extension is not loaded. Two things are required, and
BOTH are the database operator's job -- this chart cannot do either:

  a) shared_preload_libraries = pg_cron   (a STATIC parameter: it needs a
     database restart before it takes effect, even though the change applies
     cleanly without one)
  b) cron.database_name = {{ .Values.database.name }}

Also confirm INVOKR_DATABASE_URL points at the WRITER endpoint. pg_cron runs
jobs only on the writer; a reader gives you a working API and zero executions.

────────────────────────────────────────────────────────────────────────
3. BOOTSTRAP AN ORG AND WORKSPACE
────────────────────────────────────────────────────────────────────────
Invokr is multi-tenant and has no tenants until you create one. Nothing works
until this is done -- it is not automated by this chart.

  curl -X POST "$INVOKR_URL{{ include "invokr.pathPrefix" . }}/v1/orgs" \
    -H "Authorization: Bearer $INVOKR_API_KEY" \
    -H 'Content-Type: application/json' \
    -d '{"name": "your-org"}'

  curl -X POST "$INVOKR_URL{{ include "invokr.pathPrefix" . }}/v1/orgs/<org_id>/workspaces" \
    -H "Authorization: Bearer $INVOKR_API_KEY" \
    -H 'Content-Type: application/json' \
    -d '{"name": "your-workspace"}'

Creating a workspace provisions its schema, so give it a moment to complete.
